# M2 — полнотекстовый поиск по заметкам (FTS5)

Дата: 2026-11-26. Коммит: `m2-fts5-search`. Предыдущий этап: M4 (модель конфликтов).
Отчёт аудита P1: «LIKE '%word%' плохо ищет по-русски (морфология, синонимы)».

## Что сделано

- Виртуальная таблица **`notes_fts`** (`CREATE VIRTUAL TABLE ... USING fts5(body, fact_key,
  viewer_id, tokenize='unicode61')`), rowid = `notes.id`, собственное хранилище копий —
  так `snippet()` работает даже с NULL-ключами и не зависит от внешнего контента.
- **Миграция идемпотентна** (`_migrate_fts_index`, вызывается из `__init__`): схема и
  триггеры пересоздаются на каждом старте (`CREATE ... IF NOT EXISTS`, триггеры —
  drop+create, чтобы не пережить ручное удаление индекса), существующие заметки
  заполняются из `notes`. Сверка счётчиков: расхождение = рассинхронизация → полная
  пересборка из `notes` при старте + запись в `state('m2_fts')`. Молчаливый битый
  индекс невозможен.
- **Триггеры** `notes_fts_ai/ad/au` на INSERT/UPDATE/DELETE заметок — автосинхронизация
  на горячем пути (NULL-ключи/зрители нормализуются в `''`).
- **Поиск** `MemoryManager.search_notes(query, limit, viewer_id, include_history)`:
  BM25-ранжирование `bm25(notes_fts)` (меньше — лучше), сниппет `snippet()` с маркерами
  `\ue000/\ue001`, лимит ≤ 100, scoping зрителя (свои + общие, чужие — никогда).
- **Морфология**: пользовательский запрос → только `\w`-токены (не больше 8) → каждый
  токен — префиксный фраз-запрос `"токен"*`; для слов ≥ 4 символов добавляется
  `"осн"*` (первые 3 символа). Результат: «кумара» находит «Кумар», «корабли» —
  «кораблей», «люблю» — «Любимый», «читал» — «читает». Операторы FTS5 (NOT/NEAR/двоеточия)
  инъектировать нельзя — они отфильтровываются на этапе токенизации.
- **API**: `GET /api/notes/search?q=...&limit=20&viewer_id=&include_history=false` —
  только чтение, admin-токен не требуется (как `/api/search`). Ответ:
  `{query, count, mode:'fts5', results:[...snippet, fts_rank...]}`.
- **UI**: поле «FTS5-поиск по заметкам» над списком заметок в библиотеке памяти;
  результаты — сниппет с подсветкой (`<mark>`), статус-бейдж M4, ключ/зритель.
  Подсветка безопасна: клиент разбирает маркеры `\ue000/\ue001` в текстовые узлы и
  `<mark>`, HTML из тела заметки не исполняется. В «Системе» добавлен счётчик
  «FTS5-индекс заметок» (`counts.fts_notes`).

## Интеграция с M4

- По умолчанию ищется **текущая правда**: `active` + `disputed` (спор не инвалидирует
  факт). `include_history=true` подключает `superseded` и `retracted` — то же
  соглашение, что у `GET /api/notes`.
- Заменённая заметка исчезает из выдачи сразу после суперсессии (триггер-UPDATE) и
  находится по `include_history=true` со статусом `superseded`.
- Мягкое отзывание (`DELETE` без `hard`) сразу скрывает заметку из FTS-выдачи.

## Найдено и починено по ходу

- **Баг M4**: физическое удаление (`DELETE /api/notes/{id}?hard=true`) заметки, на
  которую ссылаются другие строки через `superseded_by_id`, падало с
  `FOREIGN KEY constraint failed` — внешние ссылки блокировали удаление PII. Теперь
  перед hard-удалением обнуляются указатели `superseded_by_id → удаляемая`.
  Покрыто тестом `test_triggers_keep_index_in_sync`.

## Производительность (замер, 1200 заметок)

| Запрос | Лучший из 5 |
| --- | --- |
| «корабл чай» | 3.9 мс |
| «кумара облепиховый» | 4.1 мс |
| «заметка номер 999» | 0.7 мс |
| Полная пересборка индекса (1200 строк) | 12.3 мс |

Требование «1000+ заметок < 100 мс» выполнено с запасом ~25×; тест
`test_performance_1000_notes_under_100ms` проверяет холодные и повторные запросы.

## Ограничения и честные границы

- unicode61 не стеммер: словоизменение покрывается префиксами, но словообразование
  (например «печь» ↔ «пекарня») не находится — это ожидаемая граница, а не баг.
- Морфология реализована для поиска заметок; словесный резервный поиск
  (`semantic.lexical_rank`) и смысловой слой M3 не тронуты.
- FTS5 не индексирует сообщения, лор и эфирные фрагменты — только заметки; остальной
  поиск по-прежнему идёт через `/api/search`.

## Обратимость

`tools/downgrade_m2.py [--db ...] [--yes]`: удаляются только `notes_fts`, триггеры
`notes_fts_*` и ключ `state('m2_fts')`; таблица `notes` не трогается. Срез-бэкап
`*.pre-m2-downgrade-<ts>.bak`, сухой режим по умолчанию, `integrity_check` после
изменений, повторный запуск — честный no-op. После отката словесный поиск продолжает
работать, а повторный запуск приложения заново создаёт индекс.

## Тесты

`tests/test_fts_search.py`, 24 теста: миграция и заполнение (в т.ч. базы до M2),
идемпотентность, авто-починка рассинхронизации, морфология (2 теста), безопасность
MATCH-выражения, пустые запросы, BM25-ранжирование, лимиты, триггеры (INSERT/UPDATE/
in-place/DELETE/смена зрителя), интеграция M4 (superseded/retracted/disputed/скоуп
зрителя), маркеры сниппета, API (4 теста, включая отсутствие admin-токена на чтение),
производительность 1200 заметок < 100 мс, downgrade (включая no-op и повторное
создание при открытии).
