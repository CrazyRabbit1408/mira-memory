# КУМАР — передача проекта v0.14.0-orcarouter

## Что изменилось

Проект пересобран под OrcaRouter API. Ollama больше не запускается и не выбирается в интерфейсе. Ответы идут через OpenAI-compatible endpoint `https://api.orcarouter.ai/v1`, по умолчанию модель `deepseek/deepseek-v4.1-flash-free`.

Системный промпт Кумара хранится локально в `config/character.md` — это единственный источник истины о личности. Панель собирает промпт (характер + базовые правила + эмоция) и отправляет его в каждом запросе к OrcaRouter; версия характера фиксируется отпечатком SHA-256. Внешний prompt-registry больше не участвует. API-ключ хранится только в `.env` и не попадает в backup; там же задаётся `KUMAR_ADMIN_TOKEN` для изменяющих эндпоинтов панели.

## Модель конфликтов памяти (M4)

Заметки имеют явный жизненный цикл факта. Статусы: `active` (актуальный), `superseded` (заменён новой версией), `disputed` (оспорен оператором вручную; не инвалидирует историю автоматически), `retracted` (отозван владельцем). Новые поля `notes`: `status`, `valid_from`, `valid_to`, `superseded_by_id` (ссылка старой строки на актуальную — прыжок к «что сейчас верно» за один запрос).

Правила изменения:

- **Правка текста или ключа факта** — суперсессия: старая строка получает `status='superseded'`, `valid_to=now`, ссылку на новую; новая создаётся `active` со сквозным номером ревизии. Старая строка не удаляется — история изменений сохраняется полностью и видна через «Просмотреть историю версий» (обход цепочки в обе стороны).
- **Правка только метаданных** (важность/тип/уверенность при том же тексте и ключе) — правка на месте без новой версии.
- **Удаление** — по умолчанию мягкое отзывание (`retracted`, строка и история сохраняются, факт исчезает из поиска и памяти). Физическое удаление — только `DELETE /api/notes/{id}?hard=true` под admin-токеном, для PII и нарушений.
- **Спор** — только ручная пометка оператора («Пометить спорной» в панели или `POST /api/notes/{id}/status`).

Разрешение конфликтов при сборке контекста (замена грубого «одна исправленная заметка → удалить все ответы Кумара», аудит P1.2): перед запросом к модели панель находит устаревшие факты — предков найденных заметок по цепочкам суперсессий плюс детерминированный лексический отбор отозванных/заменённых (основы слов, без эмбеддингов). Исключаются из истории только те ответы Кумара, которые реально связаны с устаревшим фактом; остальные остаются нетронутыми. Параллельно в промпт уходит отдельное system-сообщение `<conflicting_facts>` («Ранее было сказано X, но это неактуально. Актуально: Y») — оно не смешивается с характером: `config/character.md` остаётся единственным источником личности при любом провайдере.

Миграция выполняется автоматически при первом запуске: вся операция — одна транзакция `BEGIN IMMEDIATE` (индекс пересоздаётся после бэкфилла и схлопывания дублей, до любых пользовательских вставок). Существующие строки становятся `active`, `valid_from=created`. Дублирующиеся ключи фактов из баз до индекса не удаляются молча: новейшая строка остаётся актуальной, старые помечаются `superseded` со ссылкой на неё, отчёт пишется в `state('m4_migration_report')`. Откат — `python -m tools.downgrade_m4 [--db data/memory.sqlite3] --yes`: пре-проверки целостности (битые ссылки останавливают скрипт со списком ID), срез-бэкап рядом с базой, архивирование тел дубликатов в `note_versions`, пересоздание таблицы к схеме Этапа 0. Без `--yes` скрипт только показывает план.

API: `GET /api/notes?include_history=true` (по умолчанию — только `active` и `disputed`); `GET /api/notes/{id}/versions` — история цепочки; `PUT /api/notes/{id}` возвращает `mode/old_id/new_id`; `DELETE /api/notes/{id}` — отозвать, `?hard=true` — удалить физически; `POST /api/notes/{id}/status` — кураторские пометки. Все изменяющие эндпоинты по-прежнему под admin-токеном. Нюанс: физическое удаление заметки, на которую указывают `superseded_by_id` других строк, сначала обнуляет эти ссылки — иначе внешний ключ не пустил бы удаление PII.

## Полнотекстовый поиск (M2)

Заметки дополнительно индексируются FTS5-таблицей `notes_fts` (колонки `body`, `fact_key`, `viewer_id`; tokenizer `unicode61`; rowid = notes.id). Индекс — производные данные: схема и триггеры синхронизации (INSERT/UPDATE/DELETE) создаются идемпотентно при каждом старте, рассинхронизация (сравнение счётчиков) автоматически лечится полной пересборкой из `notes` при запуске; при осмысленной правке FTS обновляется триггерами, без полной пересборки на горячем пути.

Поиск: `MemoryManager.search_notes()` и `GET /api/notes/search?q=...` (только чтение, admin-токен не нужен; параметры `limit` ≤ 100, `viewer_id`, `include_history`). Пользовательский запрос превращается в безопасное MATCH-выражение: только `\w`-токены (операторы FTS5 и кавычки не могут инъектироваться), каждый токен — префиксный фраз-запрос; для слов длиннее 3 символов добавляется префикс первых трёх символов основы. Это даёт морфологию русского: «кумара» находит «Кумар», «корабли» — «кораблей», «люблю» — «Любимый». Ранжирование — `bm25(notes_fts)` (меньше — лучше), сниппет — `snippet()` с маркерами `\ue000/\ue001` вместо HTML: фронтенд экранирует текст и только потом превращает маркеры в `<mark>`, поэтому подсветка не может протащить разметку из тела заметки.

Интеграция с M4: по умолчанию ищется только «текущая правда» — `active` и `disputed` (спор не инвалидирует факт); `include_history=true` подключает `superseded` и `retracted`. При заданном `viewer_id` выдаются только общие и свои заметки, чужие — никогда. На 1200 заметках поиск выполняется за единицы миллисекунд (тест: < 100 мс). В `/api/status` добавлен счётчик `counts.fts_notes`.

Откат — `python -m tools.downgrade_m2 [--db data/memory.sqlite3] [--yes]`: удаляются только `notes_fts`, три триггера и ключ состояния `m2_fts`; таблица `notes` не затрагивается (принцип «downgrade безопаснее upgrade» — индекс и есть производные данные). Словесный резервный поиск при этом продолжает работать. Без `--yes` скрипт показывает план.

## Честный rebuild_index (M1)

`MemoryManager.rebuild_index()` раньше был misleading-заглушкой: только считал записи и вызывался после каждой мутации (в т.ч. после сохранения сообщений, которых в индексе заметок вообще нет). Теперь метод действительно пересобирает поисковый индекс: гарантирует наличие схемы `notes_fts` и триггеров (восстановление после ручного удаления таблицы — тест `test_rebuild_recovers_after_fts_table_drop`), полностью перезаливает строки из `notes` и возвращает честное число проиндексированных заметок. Возврат изменился: было «число всех записей индекса смысла», стало — число строк FTS5.

Вызовы с горячего пути убраны: обычные правки заметок и сообщений синхронизируются триггерами M2 (тест `test_mutations_do_not_call_full_rebuild` ломается, если мутация дёргает полную пересборку). Полная пересборка нужна после внешних вмешательств или по требованию оператора.

API: `POST /api/rebuild-index` под admin_guard возвращает `{indexed, mode:'fts5'}`; в панели в карточке «Индекс памяти» кнопка **«Перестроить поисковый индекс»**. Эндпоинт «Обновить индекс» лора (`/api/lore/reindex`) теперь тоже возвращает честное число заметок в FTS.

## Запуск

```bash
cd /home/kymar_x_ai/mira-memory-v1
cp .env.example .env
nano .env
chmod +x launcher/run-mira.sh
./launcher/run-mira.sh prepare
./launcher/run-mira.sh start
```

Минимальный `.env`:

```dotenv
ORCAROUTER_API_KEY=...
ORCAROUTER_BASE_URL=https://api.orcarouter.ai/v1
ORCAROUTER_SESSION_ID=kumar-panel
KUMAR_SEMANTIC_SEARCH=0
KUMAR_ADMIN_TOKEN=...
```

Панель: `http://127.0.0.1:8000`.

## Backstage

- **Сбросить сессию LLM** — создаёт новый Session-Id OrcaRouter: следующий запрос уходит с новым заголовком `X-OrcaRouter-Session-Id`; локальная история в SQLite сохраняется;
- **Остановить/возобновить TTS** — переключает текущую заглушку, чтобы будущий TTS можно было заменить без изменения панели;
- **Внедрить фрагмент** — добавляет временное или постоянное воспоминание Кумара прямо во время эфира.

## Ограничения текущей сборки

- Бесплатные лимиты и доступность моделей определяет OrcaRouter; они не являются лимитом отдельных ключей.
- TTS пока пишет последнюю фразу в `data/last_tts.txt`, звука нет.
- Ollama и `qwen3-embedding` отключены. Поиск памяти пока словесный.
- Резервная копия не включает `reference/*` — приватный авторский архив остаётся только на диске.
- Twitch и чат-платформа пока не подключены.
- Диалоговый ответ приходит одним куском: стриминг (SSE) ещё не реализован. Подготовленный план — `reports/streaming-l2-plan.md` (L2-prep): OrcaRouter поддерживает `stream: true` (SSE, `data:`-кадры, `[DONE]`, `stream_options.include_usage`); план из 5 шагов с fallback на полный ответ и политикой обработки ошибок в середине потока.

## Обновление

Не распаковывайте новую версию поверх работающей папки. Сначала остановите панель, скопируйте `data/`, затем распакуйте архив в новую папку и перенесите только свой `.env` и нужную базу.
